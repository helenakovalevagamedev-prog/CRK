# Тестовое задание Unity: кликер, погода, породы собак

Приложение из трёх вкладок с нижней навигацией:

1. **Кликер** — валюта, энергия, автосбор, эффекты нажатия.
2. **Погода** — прогноз с api.weather.gov, обновляется каждые 5 секунд.
3. **Породы собак** — список пород с dogapi.dog и попап с описанием породы.

Все запросы к серверу проходят через общую очередь и выполняются строго по одному.

## Запуск

* **Unity 2022.3.62.f3 LTS**
* Открыть сцену `Assets/Scenes/MainScene.unity` и нажать Play.
* Рекомендуемое разрешение окна Game — **1080 × 1920** (портрет). UI адаптируется и под другие разрешения.

## Архитектура

### Общие принципы

* **MVP.** Каждая вкладка разделена на модель или сервис (данные и логика), View (MonoBehaviour, только отображение и события ввода) и Presenter (связывает их, обычный C#-класс).
* **DI вместо Singleton.** Ни одного статического `Instance`. Все зависимости приходят через конструктор, а в MonoBehaviour — через `\[Inject]`-метод. Все привязки описаны в одном месте, в `GameInstaller`.
* **Зависимость от интерфейсов.** Сервисы (`IRequestQueue`, `IHttpClient`, `ITabsService`, `IWeatherService`, `IDogsService`) используются через интерфейсы, поэтому их реализации можно подменить в инсталлере.
* **Настройки в ScriptableObject.** Числа баланса, интервалы, адреса API и параметры анимаций не зашиты в код.

## Очередь запросов

`RequestQueue` — центральная часть сетевого слоя.

```csharp
UniTask<T> Enqueue<T>(string tag, Func<CancellationToken, UniTask<T>> request, CancellationToken externalToken = default);
void Cancel(string tag);
```

* В очередь передаётся **функция, создающая запрос**, а не уже запущенный запрос. Поэтому запрос стартует только тогда, когда до него дошла очередь.
* `Enqueue` сразу возвращает `UniTask<T>`, которую вызывающий код может `await`-ить. Результат, отмена или ошибка придут через неё (внутри `UniTaskCompletionSource<T>`).
* Обработчик берёт первый элемент, дожидается его полного завершения и только потом берёт следующий.
* Ожидающие запросы хранятся в `LinkedList`, чтобы их можно было удалять из середины очереди.
* У каждого элемента свой `CancellationTokenSource`, связанный с внешним токеном вызывающего (`CreateLinkedTokenSource`). Отмена работает так:

  * **запрос ждёт в очереди** — он сразу удаляется из очереди, вызывающий получает отмену;
  * **запрос выполняется** — токен прерывает `UnityWebRequest` (через `WithCancellation`, который вызывает `Abort`), и очередь переходит к следующему запросу.
* Ошибка одного запроса не останавливает очередь.
* При уничтожении контекста (`IDisposable`) все оставшиеся запросы отменяются.

Презентеры отменяют свои запросы через собственный `CancellationTokenSource`, токен которого передаётся по цепочке «презентер → сервис → очередь → HTTP-клиент». Одно `Cancel()` останавливает и ожидание в очереди, и выполняющийся запрос. Также поддерживается отмена по метке: `Cancel(tag)`.

## Вкладки

### Кликер

* Ручной клик и автосбор вызывают **один и тот же** метод `TryCollect(energyCost)`. Поэтому автосбор проигрывает все те же эффекты, а логика не дублируется.
* Если энергии не хватает, сбор не происходит.
* Таймеры (`AutoCollector`, `EnergyRegenerator`) реализуют `ITickable` и накапливают `Time.deltaTime`. Остаток интервала переносится на следующий цикл, поэтому таймер не «уезжает».
* **Эффекты:** `DOPunchScale` для кнопки, `AudioSource.PlayOneShot` со случайным разбросом высоты звука, `ParticleSystem.Emit` для частиц, вылетающий текст из пула. Canvas в режиме Screen Space - Camera, чтобы частицы рисовались поверх UI.

### Погода

* Пока вкладка открыта, каждые 5 секунд в очередь ставится новый запрос. Цикл не ждёт ответа предыдущего запроса, поэтому интервал постановки ровно 5 секунд, а последовательность выполнения обеспечивает очередь.
* Прогноз и иконка — два отдельных запроса, оба идут через очередь. Иконки кэшируются по URL.
* api.weather.gov требует заголовок `User-Agent`, он выставляется в `UnityHttpClient`.
* При уходе с вкладки опрос останавливается, а ожидающий и выполняющийся запросы отменяются.

### Породы собак

* При каждом открытии вкладки список запрашивается заново, пока идёт загрузка, показывается лоадер. Строки списка берутся из пула.
* По клику на породу её данные запрашиваются по `id` (`/api/v2/breeds/{id}`), пока данные идут, у строки крутится индикатор.
* Клик по другой породе отменяет предыдущий запрос (удаляет его из очереди или прерывает), убирает его индикатор и ставит новый запрос. Индикатор убирается синхронно в момент отмены, поэтому опоздавшее завершение отменённого запроса не может выключить индикатор новой породы.
* Повторный клик по породе, которая уже загружается, игнорируется.
* Попап один на все породы. Высота подстраивается под текст через `Vertical Layout Group` + `Content Size Fitter`.
* При уходе с вкладки отменяются запросы списка и деталей, попап закрывается.

## Пулы объектов

Используется `Zenject.MonoMemoryPool`:

* `FlyingTextPool` — вылетающий текст кликера (начальный размер 10);
* `BreedItemPool` — строки списка пород (начальный размер 10).

Объекты не создаются и не уничтожаются на каждое действие, а переиспользуются. При взятии из пула объект сбрасывается в исходное состояние, при возврате у него снимаются подписки на события.

## Адаптивность

* `Canvas Scaler`: Scale With Screen Size, эталон 1080 × 1920, Match 0.5.
* Элементы привязаны якорями к краям или центру экрана.
* Раскладка через Layout Group, высота попапа через Content Size Fitter.

## Принятые решения

* **Таймеры кликера работают и на других вкладках.** По ТЗ валюта начисляется, «даже если игрок ничего не делает». Визуальные эффекты и звук проигрываются, только когда вкладка кликера видна.
* **Отдельный запрос описания по id**, хотя описание есть и в ответе со списком. Так требует ТЗ.
* **JsonUtility** вместо сторонних JSON-библиотек: структура ответов простая, а лишние поля он пропускает.
* **Обработка ошибок:** при сетевой ошибке показывается сообщение («Не удалось загрузить погоду», «Не удалось загрузить породы», ошибка в попапе), опрос погоды продолжает работать. Отмена ошибкой не считается.

## Что можно улучшить

* Юнит-тесты для `RequestQueue` и презентеров (архитектура это позволяет за счёт интерфейсов).
* Сохранение прогресса кликера между запусками.
* Повтор запросов при ошибке сети с задержкой (retry/backoff).
* Прокрутка в попапе для очень длинных описаний.
